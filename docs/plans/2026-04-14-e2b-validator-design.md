# E2B Validator Design

**Date:** 2026-04-14
**Status:** Approved

## Overview

A Claude Code skill (`/validate`) that lets Claude verify its own code changes end-to-end in an isolated E2B sandbox — the way a real developer would: running the full docker compose stack, hitting the API with curl, querying Postgres, triggering Temporal workflows, and navigating the browser UI.

The motivation: multiple worktrees run simultaneously on the same machine, so port conflicts prevent running the stack locally per-worktree. E2B provides fully isolated, ephemeral environments with no port conflicts.

---

## Architecture

```
Main Claude (worktree)
  │
  ├─ finishes implementation
  ├─ invokes /validate skill
  │
  └─ skill tells Claude to:
       1. Inspect git diff → derive specific validation steps
       2. git commit + push branch
       3. node scripts/e2b-validate.mjs --prompt "<steps>" --retries=2
       │
       └─ e2b-validate.mjs
            ├─ create E2B sandbox (custom template: claude + Docker + tools)
            ├─ sandbox.git.clone(repo, branch)
            ├─ docker compose up -d (poll healthchecks, max 120s)
            ├─ claude --dangerously-skip-permissions --output-format json -p "<prompt>"
            │    └─ validator Claude: curl / psql / temporal CLI / Playwright scripts
            ├─ parse JSON result from stdout
            ├─ sandbox.kill()
            └─ exit with result

  skill reads result
  ├─ passed → report success to user
  └─ failed + retries > 0 → show failures to main Claude → fix → retry
```

## Components

### 1. Skill: `.claude/skills/validate.md`

Built using the `skill-creator` skill.

When invoked, instructs Claude to:
1. Run `git diff main...HEAD` to understand what changed
2. Derive a numbered list of concrete, specific validation checks with expected values (status codes, DB states, UI elements) — generated by Claude, not provided by the user
3. Commit and push: `git add -A && git commit && git push -u origin <branch>`
4. Run: `node scripts/e2b-validate.mjs --prompt "<generated steps>" --retries=2`
5. Parse the result and either declare success or fix failures and retry

### 2. Orchestrator: `scripts/e2b-validate.mjs`

Node.js ESM script using the E2B TypeScript SDK.

**Arguments:**
- `--prompt` — validation steps string (required)
- `--retries` — max retry attempts (default: 2)
- `--branch` — auto-detected from `git branch --show-current`
- `--repo` — auto-detected from `git remote get-url origin`

**Flow:**
1. Parse args, read env vars
2. `Sandbox.create(E2B_TEMPLATE_ID, { envs: { ANTHROPIC_API_KEY, GITHUB_TOKEN } })`
3. `sandbox.git.clone(repo, { path: '/app', branch, username: 'x-access-token', password: GITHUB_TOKEN, depth: 1 })`
4. `sandbox.commands.run('cd /app && docker compose up -d')` — poll until all healthchecks pass (max 120s)
5. `sandbox.commands.run('cd /app && claude --dangerously-skip-permissions --output-format json -p "<prompt>"', { timeoutMs: 300_000 })`
6. Parse `result.stdout` as JSON
7. `sandbox.kill()`
8. Print result JSON to stdout; exit 0 if passed, 1 if failed

### 3. E2B Template: `scripts/e2b-template/`

Custom template built on top of E2B's pre-built `claude` template (Claude Code already installed).

```ts
// scripts/e2b-template/template.ts
import { Template } from 'e2b'
export const template = Template()
  .fromTemplate('claude')
  .aptInstall(['docker.io', 'docker-compose-plugin', 'postgresql-client', 'curl'])
  .runCommands([
    'curl -sSf https://temporal.download/cli.sh | sh',
    'mv temporal /usr/local/bin/temporal',
  ])
  .npmInstall(['playwright'], { g: true })
  .runCommands(['playwright install chromium --with-deps'])
```

Built once with `npx tsx scripts/e2b-template/build.ts`. The resulting template ID is stored in `.env` as `E2B_TEMPLATE_ID`.

### 4. Validator Claude (inside sandbox)

Receives a two-part prompt:

**Part 1 — Stack context (static):**
```
You are a validator running inside an E2B sandbox.
Services running via docker compose:
- Web (React): http://localhost:5173
- API (Fastify): http://localhost:3000
- Temporal UI: http://localhost:8233
- Postgres: localhost:5432 (user: postgres, pass: postgres, db: hello_world)

Available tools: curl, psql, temporal CLI, Node.js (write + run Playwright scripts for UI checks).
```

**Part 2 — Validation steps (generated by main Claude from diff):**
```
Validate the following:
1. GET http://localhost:3000/healthz → 200
2. POST http://localhost:3000/ping → 202, inserts row with status=pending in DB
3. Within 3s, row status=done in DB
4. Navigate to http://localhost:5173, click "Send Ping", verify UI shows "done"

For each check: run it, record pass/fail and actual result.
```

## Environment Variables

Three keys required, all in `.env` (gitignored):

| Key | Used by | Purpose |
|-----|---------|---------|
| `E2B_API_KEY` | orchestrator (host) | Authenticate with E2B |
| `ANTHROPIC_API_KEY` | passed into sandbox | Claude Code inside E2B |
| `GITHUB_TOKEN` | passed into sandbox | Clone private repo |
| `E2B_TEMPLATE_ID` | orchestrator (host) | Which sandbox template to use |

`.env.example` documents all four keys.

---

## Retry Loop

Managed by the skill, not the orchestrator. The orchestrator always does exactly one run.

```
retries = 2 (default, configurable)

loop:
  run orchestrator → result
  if passed → done
  if failed AND retries > 0:
    show failures to main Claude
    main Claude fixes issues
    git commit + push
    retries--
    repeat
  if failed AND retries = 0:
    report remaining failures to user, stop
```

---

## Error Handling

| Scenario | Behavior |
|----------|----------|
| `docker compose` healthcheck timeout (>120s) | `{ passed: false, error: "services failed to start" }` |
| Validator Claude timeout (>5min) | `{ passed: false, error: "validator timed out" }` |
| stdout not valid JSON | `{ passed: false, error: "parse failed", raw: "..." }` |
| Sandbox creation failure | Throw immediately, no retry consumed |
